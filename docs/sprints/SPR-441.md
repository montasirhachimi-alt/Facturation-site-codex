# SPR-441 — HR Leave, Absence & Attendance Operations V1

## Summary

SPR-441 turns the SPR-440 HR Alpha foundation into day-to-day HR Operations for leave, absence and simple attendance administration.

The operational chain is now:

```text
Employee
  -> Leave entitlement/balance
  -> Leave request
  -> Approval / rejection / cancellation
  -> Approved absence visibility
  -> HR agenda
  -> Daily attendance state
  -> Employee operational HR summary
```

No payroll, biometric time clock, statutory Moroccan payroll/CNSS/IR, shift engine, overtime engine, GPS tracking, medical records, recruitment, performance or AI HR Agent capability was introduced.

## Repository Reconciliation

SPR-440 provided the canonical Alpha HR source of truth:

- `HrDepartment`
- `HrPosition`
- `HrEmployee`
- `HrEmploymentContract`
- `HrLeaveType`
- `HrLeaveRequest`

Current `HrLeaveType` was extended rather than replaced. It now supports `code`, `paid`, `approvalRequired`, `balanceTracked`, optional `defaultAnnualEntitlement`, `active` and optional `description`.

Current `HrLeaveRequest` was extended rather than replaced. It preserves existing SPR-440 requests and adds decision metadata:

- `decidedAt`
- `decisionByEmployeeId`
- `decisionNote`

Existing statuses remain:

```text
draft, requested, approved, rejected, cancelled, archived
```

`HrEmployee.managerEmployeeId` remains the manager relationship. `HrEmployee.linkedUserId` remains optional and suitable for future self-service identity linkage, but SPR-441 does not force every employee to have a login.

Legacy payroll-era `Employee`, `Attendance`, `HrLeave`, `SalarySlip`, `SalaryAdvance` and `HrDocument` models remain isolated and are not reused as Alpha HR Operations truth.

## Leave Type Operations

Leave types now support pragmatic V1 configuration:

- code;
- name;
- active flag;
- paid/unpaid classification;
- approval required;
- balance tracked;
- optional default annual entitlement;
- optional description.

Examples remain business-configurable, such as `Congé payé`, `Congé sans solde`, `Maladie` and `Autorisation exceptionnelle`. No statutory leave law is encoded.

## Leave Balance Architecture

SPR-441 adds tenant-scoped `HrLeaveBalance`.

Identity:

```text
tenantCompanyId + employeeId + leaveTypeId + periodYear
```

Stored source-of-truth values:

- `entitledDays`
- `adjustmentDays`
- `adjustmentReason`

Derived values:

```text
usedDays      = approved leave request days
pendingDays   = requested leave request days
remainingDays = entitledDays + adjustmentDays - usedDays
```

This avoids independently mutable used/pending/remaining totals.

## Leave Calculation Rules

V1 uses inclusive calendar days from `startDate` to `endDate`.

SPR-441 intentionally does not implement weekends, public holidays, monthly accrual, seniority, carry-over, payroll deduction or country-specific statutory calculations.

Negative remaining balance is rejected when a balance-tracked leave type is approved.

## Leave Request Lifecycle

Allowed transitions:

```text
draft -> requested | cancelled | archived
requested -> approved | rejected | cancelled | archived
approved -> cancelled | archived
rejected -> archived
cancelled -> archived
archived -> no transition
```

Invalid transitions are rejected by the HR service. Repository persistence preserves tenant ownership for employees, leave types and decision actors.

## Approval Architecture

V1 supports HR-admin operational approval. Decision metadata stores:

- actor employee id when available;
- decision timestamp;
- optional decision note.

The manager relationship remains available as the future default approver foundation. SPR-441 does not introduce a new permissions engine and does not require each employee to be an authenticated user.

## Absence Architecture

SPR-441 adds tenant-scoped `HrAbsence` for manual HR absence records.

Approved leave requests are visible as leave-derived absences without requiring HR to enter the same absence twice.

Sources:

- `leave`: derived visibility from approved `HrLeaveRequest`;
- `manual`: persisted `HrAbsence`.

Rejected or cancelled leave does not create approved absence visibility.

## Attendance Architecture

SPR-441 adds tenant-scoped `HrAttendanceRecord` for simple daily attendance declaration.

Identity:

```text
tenantCompanyId + employeeId + date
```

Statuses:

```text
present, absent, leave, remote, partial, other
```

This is operational daily state only. It is not clock-in/clock-out, payroll hours, timesheets, overtime, shift scheduling, GPS or biometric attendance.

## Consistency Rules

- Requested leave is pending and does not consume approved balance.
- Approved leave consumes balance.
- Rejected leave consumes nothing.
- Cancelled approved leave no longer contributes to consumption.
- One employee can have only one attendance record per date.
- A user cannot mark an employee `present` on an approved leave date without first resolving the leave.
- If no attendance record or approved leave/absence exists, current workforce state is `Non renseigné`, not assumed present.

## Known Limitations

- Calendar days are counted inclusively; weekends and public holidays are not configured.
- Leave entitlement is manual per employee/type/year.
- No monthly accrual, carry-over, seniority or statutory leave calculation.
- Approval is HR-admin operational approval with future manager approval foundations preserved.
- No payroll, salary deduction, attendance payroll hours, overtime or shift scheduling.
- No employee self-service portal.
- No medical details should be stored.
