# SPR-440 — HR Core / RH Alpha Foundation V1

## Summary

SPR-440 introduces the canonical HR Core Alpha foundation for BOSIACO.

The new RH workspace is focused on employee administration:

- employees;
- departments;
- positions;
- simple employment contracts;
- simple leave requests.

It intentionally does not introduce payroll, time clocks, salary advances, performance management, training, recruitment pipelines or accounting automation.

## Root Cause

The repository already contained legacy HR-era Prisma models and `/rh/*` routes, but they were not suitable as the active Alpha HR source of truth.

The legacy model mixed employee administration with payroll-sensitive concepts and old route placeholders. It also risked confusing the business concept of an Employee with an authenticated BOSIACO User.

## Architecture

SPR-440 adds a canonical HR module under `src/modules/hr/`:

- `HrService` owns deterministic local/session behavior.
- `hrLocalService` acts as the client cache and subscription source.
- `/api/persistence/hr` resolves the authenticated tenant scope.
- `hr-repository` persists tenant-scoped HR records through Prisma.
- `HrPersistenceProvider` hydrates HR data in the ERP shell.
- `hrSearchProviders` integrates employees into Unified Search.

UI components do not call Prisma directly.

## Persistence Models

Added canonical tenant-scoped Prisma models:

- `HrDepartment`
- `HrPosition`
- `HrEmployee`
- `HrEmploymentContract`
- `HrLeaveType`
- `HrLeaveRequest`

Legacy `Employee`, `EmployeeContract`, `Attendance`, `HrLeave`, `SalarySlip`, `SalaryAdvance` and `HrDocument` models remain untouched for compatibility.

## Employee vs Auth User

An HR Employee is a business/personnel record.

An authenticated User is an application access identity.

SPR-440 keeps them separate. `HrEmployee.linkedUserId` is optional and tenant-checked, so future self-service HR or permission-aware employee experiences can be introduced without forcing every employee to be a login user.

## Workspace

The canonical Alpha route is:

```text
/rh
```

The workspace includes:

- Vue d'ensemble
- Employés
- Départements
- Postes
- Contrats
- Congés

Legacy RH subroutes redirect to `/rh` to avoid exposing incomplete payroll-era surfaces.

## Lifecycle and Validation

Employee statuses:

- active
- inactive
- on_leave
- terminated
- archived

The service and repository validate:

- required employee number;
- required employee identity;
- unique employee number in the local service;
- department/position/manager existence;
- self-manager rejection;
- optional linked user tenant ownership;
- contract employee/position relationships;
- leave employee/type relationships;
- leave end date after start date.

## Search and Navigation

`hr.employees` is promoted to an Alpha-ready module and added to default `alpha.crm-sales`.

The Sidebar and Command Center expose `/rh` through activation metadata. Unified Search can return hydrated employee records when HR data is available.

## Known Limitations

- Payroll is not implemented.
- Attendance/time clock is not implemented.
- Salary advances and salary slips remain legacy/out of scope.
- Recruitment, performance, training and org chart visualization are future capabilities.
- Leave requests are a minimal lifecycle foundation and do not calculate balances.
