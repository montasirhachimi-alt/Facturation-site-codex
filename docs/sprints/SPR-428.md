# SPR-428 — Procurement Analytics & Cockpit Enrichment

## Objective

SPR-428 enriches the existing `/procurement` overview into a stronger Procurement business cockpit.

This sprint does not rebuild Procurement. It keeps the existing operational foundation:

- Suppliers
- Purchase Orders
- Goods Receipts
- partial receipts
- Inventory `RECEIPT` posting
- Procurement persistence
- Sidebar, Command Center, Unified Search and Dashboard integration

The goal is decision support using real persisted Procurement data.

## Previous Procurement State

Before SPR-428, `/procurement` already showed:

- Brouillons
- À réceptionner
- Stock faible
- Commandes à recevoir
- Réapprovisionnement
- Réceptions récentes
- quick navigation to suppliers, purchase orders and receipts

The workflow was operational. The weakness was analytical depth.

## Data Capability Audit

| Candidate metric | Status | Reason |
| --- | --- | --- |
| Achats du mois | Supported | Purchase Orders have issue dates, statuses, lines and totals. Draft, cancelled and archived orders are excluded. |
| Montant engagé | Supported | Confirmed and partially received Purchase Orders represent active commitments. |
| Commandes ouvertes | Supported | Sent, confirmed and partially received statuses are canonical open states. |
| À réceptionner | Supported | Existing receipt-state calculation derives remaining quantities from posted Goods Receipts. |
| Réceptions partielles | Supported | `partially_received` is a canonical Purchase Order status. |
| Fournisseurs actifs | Supported | Suppliers already expose `active` and `status`. |
| Évolution des achats | Supported | Purchase Order issue dates and totals allow a deterministic six-month trend. |
| Commandes par statut | Supported but not selected | Useful, but less decision-oriented than supplier concentration for this cockpit. |
| Top fournisseurs | Supported | Purchase Orders preserve canonical supplier IDs and names. |
| Retards | Partially supported | Purchase Orders have optional expected dates, but the field is not mandatory enough to expose a reliable delay KPI yet. |
| Supplier performance | Unsupported | No delivery quality, delay policy, invoice matching or scoring source exists yet. |

## Metrics Implemented

`Achats du mois`

- Sum of validated Purchase Order totals during the current calendar month.
- Included statuses: `sent`, `confirmed`, `partially_received`, `received`.
- Excluded statuses: `draft`, `cancelled`, `archived`.
- Includes a safe comparison with the previous calendar month when there is a valid previous value.

`Montant engagé`

- Sum of Purchase Order totals with status `confirmed` or `partially_received`.
- Represents active purchasing commitments not yet fully closed.

`Commandes ouvertes`

- Count of Purchase Orders with status `sent`, `confirmed` or `partially_received`.

`À réceptionner`

- Count of confirmed or partially received Purchase Orders whose receipt state still has remaining quantity.

`Fournisseurs actifs`

- Count of Suppliers with `active === true` and `status === "active"`.

`Stock faible`

- Existing Product Catalog plus Inventory projection preserved.
- Counts stockable Products whose inventory summary is low or out of stock.

## Analytics Implemented

`Évolution des achats`

- Six-month chronological bar visualization.
- Uses validated Purchase Order value by issue month.
- Excludes draft, cancelled and archived Purchase Orders.
- Empty months render as zero values instead of disappearing.

`Top fournisseurs`

- Ranks suppliers by validated Purchase Order value.
- Aggregates by canonical `supplierId`.
- Excludes draft, cancelled and archived Purchase Orders.
- Shows order count and value for the top five suppliers.

## Regression Coverage

Runtime validation now covers:

- cancelled and draft Purchase Orders are excluded from purchase value analytics;
- current month and previous month boundaries are deterministic;
- month-over-month percentage is zero-safe;
- committed amount uses confirmed and partially received statuses;
- open PO count uses sent, confirmed and partially received statuses;
- partial receipt count uses the canonical `partially_received` status;
- active supplier count uses existing Supplier status semantics;
- monthly trend returns ordered six-month keys;
- empty datasets preserve zero values;
- top suppliers rank by validated Purchase Order value.

Existing Procurement runtime validation remains responsible for:

- supplier creation;
- Purchase Order creation;
- Purchase Order totals;
- partial and final Goods Receipt state;
- Goods Receipt line identity;
- supplier import/export foundation;
- activation and route availability.

## Known Limitations

- Supplier invoices are not implemented.
- Supplier payments are not implemented.
- Purchase approval workflows are not implemented.
- Returns and Goods Receipt reversal remain future work.
- Supplier performance scoring is not implemented because no reliable scoring source exists.
- Delay analytics are not exposed because expected delivery dates are optional.
- No new generic BI or cockpit framework was introduced.
