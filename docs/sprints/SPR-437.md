# SPR-437 — Inventory Valuation & COGS Accounting V1

## Summary

SPR-437 establishes the first trustworthy bridge between physical Inventory and canonical Accounting.

BOSIACO now has a durable inventory valuation layer that can reconstruct stock value from posted stock movements, preserve historical outbound cost, and generate controlled COGS accounting entries through the existing Finance posting architecture.

## Repository Reconciliation

The canonical physical stock source is `InventoryStockMovement`.

Current stock increases:

- Procurement Goods Receipt posting creates posted `RECEIPT` movements.
- Manual inventory receipts and positive adjustments create posted inbound movements.

Current stock decreases:

- Sales Delivery Note posting creates posted `ISSUE` movements.
- Manual inventory issues and negative adjustments create posted outbound movements.

Delivery Notes and Goods Receipts already use the Inventory posting engine. SPR-437 does not replace that physical stock truth.

Product Catalog provides current purchase cost and currency. Procurement Purchase Order lines provide supplier purchase cost, discount and currency. `InventoryStockMovement` did not store immutable cost, so historical COGS could not safely be recalculated from mutable Product cost alone.

## Valuation Architecture

Added durable `InventoryValuationEvent` records.

Each valuation event stores:

- tenant company;
- Product;
- warehouse;
- source movement;
- event type: inbound or outbound;
- valuation method;
- quantity;
- unit cost;
- total value;
- currency;
- source type/source id;
- valuation timestamp.

`movementId` is unique, so one physical movement can create only one valuation event.

## Valuation Method

V1 uses one method:

```text
moving_average_v1
```

Inbound movements increase valued quantity and total value. Outbound movements consume the current moving-average value and store the consumed amount durably.

Monetary arithmetic is performed in integer minor units before being persisted/displayed.

## Inbound Valuation

Goods Receipt valuation uses the related Procurement Purchase Order line:

- unit cost;
- discount rate;
- supplier order currency.

Manual inbound movements may use Product Catalog purchase cost only when the current product has a positive cost.

SPR-437 rejects missing/zero cost rather than silently valuing stock at zero.

## Goods Receipt / Supplier Bill Accounting Decision

Supplier Bills already post in SPR-436 as:

- debit purchase/expense;
- debit recoverable tax where configured;
- credit accounts payable.

SPR-437 therefore does not automatically post inbound `Dr Stock / Cr GRNI`.

Reason: doing so without a full GRNI/3-way matching architecture would risk double-recognizing procurement cost.

V1 decision:

- Goods Receipts establish inventory valuation.
- Supplier Bills continue to own AP/purchase expense posting.
- Automated inbound GL capitalization is deferred until a proper GRNI clearing architecture exists.

## Outbound Valuation / COGS

Outbound valuation events generated from posted Inventory `ISSUE` movements can be posted to Accounting as:

```text
Dr Cost of Goods Sold
Cr Inventory Asset
```

The source is the durable `InventoryValuationEvent`, not the mutable current Product cost.

Accounting entries use:

- `sourceType = inventory.cogs`;
- `sourceId = InventoryValuationEvent.id`.

The existing Accounting unique source constraint preserves durable idempotency.

## Accounting Configuration

Finance now owns tenant-scoped Inventory Accounting settings:

- Inventory journal;
- Inventory Asset account;
- COGS account;
- functional currency.

Posting refuses missing mappings and currency mismatch.

## Period Control

COGS posting reuses the canonical Accounting Period rules from SPR-435.

If the valuation event date belongs to a closed period, posting is rejected server-side.

## Reversal Behavior

Inventory-generated COGS entries are normal posted `AccountingJournalEntry` records.

They are compatible with the existing canonical reversal workflow. Accounting reversal does not mutate physical stock. Physical inventory correction remains a separate Inventory operation.

## UI Impact

Finance adds:

- `Intégration stock`;
- inventory posting settings;
- outbound valuation events ready for COGS posting;
- posted/reversed/not-posted status;
- an explicit note that inbound Stock/GRNI accounting is deferred.

Inventory adds:

- stock value KPI;
- `Synchroniser valorisation`;
- average unit cost and total value columns in the Stock table.

No Delivery Note, Procurement, Sales or accounting statement redesign was performed.

## Deferred Scope

Deferred intentionally:

- FIFO/LIFO;
- landed costs;
- standard costing;
- manufacturing costing;
- GRNI/3-way matching;
- supplier payment/AP settlement;
- inventory adjustments accounting beyond valuation readiness;
- FX conversion;
- automatic background posting;
- stock reversal workflows;
- statutory tax/localization reporting.
