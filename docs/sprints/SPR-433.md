# SPR-433 — Commercial Accounting Integration V1

## Summary

SPR-433 establishes the first controlled bridge between Sales operations and Accounting.

Supported source documents:

- Sales Invoice
- Sales Payment

The implementation does not redesign Sales, Finance, Runtime or business workflows. It adds a Finance-owned posting boundary that converts eligible commercial sources into canonical posted Accounting journal entries.

## Architecture

Flow:

```text
Sales source
  -> Commercial Accounting mapping
  -> canonical Accounting journal entry
  -> validation
  -> posted AccountingJournalEntry
  -> General Ledger / Trial Balance
```

Sales never writes Accounting table structure directly. The Accounting repository owns:

- commercial posting settings;
- tenant/account/journal validation;
- source idempotency;
- generated journal entry persistence;
- posted-entry validation.

## Configuration

SPR-433 adds tenant-scoped `AccountingCommercialPostingSettings`.

Configurable fields:

- Sales journal
- Receivable account
- Revenue account
- Settlement account
- Optional tax payable account
- Functional currency

No account is selected silently. Missing required mappings fail with a clear error.

## Posting Rules

Invoice posting:

- debit Receivable for invoice total;
- credit Revenue for net revenue;
- credit Tax Payable only when invoice tax exists and a tax account is configured.

Payment posting:

- debit Settlement;
- credit Receivable.

Rejected sources:

- draft invoices;
- cancelled invoices;
- draft payments;
- cancelled payments;
- sources whose currency differs from configured functional currency.

## Idempotency

Generated entries store:

- `sourceType`
- `sourceId`

The database enforces:

```text
tenantCompanyId + sourceType + sourceId
```

as unique, so repeated posting returns the existing accounting history instead of creating duplicates.

## UI Impact

Finance Operations gains an `Intégration ventes` tab.

The tab allows users to:

- configure commercial posting accounts;
- review final Sales invoices;
- review recorded Sales payments;
- see whether each source is already accounted;
- trigger `Comptabiliser` explicitly.

Sales pages were not redesigned.

## Persistence

Added:

- `AccountingCommercialPostingSettings`
- source uniqueness on `AccountingJournalEntry`

Generated entries are stored as posted entries and immediately appear in:

- Écritures comptables
- Grand livre
- Balance

## Validation

Runtime validation covers:

- invoice posting;
- payment posting;
- balanced generated entries;
- source identity;
- General Ledger contribution;
- Trial Balance contribution;
- draft source rejection;
- missing tax account rejection;
- currency mismatch rejection;
- repository source idempotency structure;
- tenant-scoped posting settings.

Canonical commands run:

- `npx prisma format`
- `npx prisma validate`
- `npx prisma generate`
- `npm run validate:runtime`
- `npm run typecheck`
- `npm run build`
- `git diff --check`
