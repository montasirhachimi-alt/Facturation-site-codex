# SPR-427 — Safe Sales Operations Profile Switch & Authenticated Alpha QA

Date: 2026-08-15

## Executive Summary

SPR-427 adds a safe local/internal profile switch for Sales Operations QA without promoting Sales Operations to default Alpha.

The profile resolver now supports the internal `sales-operations` Edition profile through a development/test-only environment variable:

```bash
NEXT_PUBLIC_BOSIACO_INTERNAL_EDITION_PROFILE=sales-operations npm run dev
```

Default runtime remains `alpha.crm-sales`.

Final sprint state: **AUTHENTICATED QA BLOCKED**.

The internal profile switch works and gated Sales Operations routes become available under a valid local authenticated session. Full browser QA through the login flow could not be completed because the demo password required for the authenticated environment is not documented in the repository, and the in-app browser session could not be safely seeded through cookie injection.

## Previous Blocker

SPR-426 left Sales Orders, Delivery Notes and Shipments hardened but gated because the only practical activation path was manually editing `defaultForEnvironment`.

That manual path was not acceptable for repeatable QA because it risked accidental Alpha promotion.

## Profile Resolution Before SPR-427

Before SPR-427:

- `src/platform/editions/edition.current.ts` selected the default Edition from the registry.
- `alpha.crm-sales` remained the default profile.
- `sales-operations` existed as an internal profile but had no safe runtime switch.
- Testing Sales Operations required a code edit to profile metadata.

## Safe Internal Profile Switch

SPR-427 introduces:

- `src/platform/editions/edition-profile.resolver.ts`
- `NEXT_PUBLIC_BOSIACO_INTERNAL_EDITION_PROFILE`
- an allow-list containing only:
  - `alpha.crm-sales`
  - `sales-operations`

The resolver is consumed by `edition.current.ts`, so Module Activation, Sidebar, route availability and Command Center consumers continue to use one activation source.

Local Sales Operations QA command:

```bash
NEXT_PUBLIC_BOSIACO_INTERNAL_EDITION_PROFILE=sales-operations npm run dev
```

Restore default Alpha:

```bash
npm run dev
```

or explicitly:

```bash
NEXT_PUBLIC_BOSIACO_INTERNAL_EDITION_PROFILE=alpha.crm-sales npm run dev
```

## Environment / Security Guard

The internal switch is intentionally constrained:

- allowed only when `NODE_ENV` is `development` or `test`;
- ignored in production builds/runtime;
- ignores unknown or non-allow-listed profile IDs;
- does not read URL parameters;
- does not read cookies;
- does not read localStorage;
- does not read request headers;
- does not create a tenant-facing Edition selector;
- does not create licensing, billing, feature flags or admin module management.
