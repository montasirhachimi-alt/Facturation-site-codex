# SPR-431 — General Ledger & Trial Balance Foundation V1

Status: Completed
Date: 2026-08-17

## Summary

SPR-431 adds the first Accounting reporting foundation for BOSIACO:

- General Ledger read model.
- Trial Balance read model.
- Server-side report query helpers.
- Runtime validation for official balance rules.

This sprint does not activate Finance in Alpha and does not create an Accounting UI.

## Scope

The General Ledger and Trial Balance are derived from canonical posted journal entry lines:

```text
AccountingJournalEntry(status = posted)
        ↓
AccountingJournalEntryLine
        ↓
General Ledger / Trial Balance read models
```

No new Prisma models, migrations, balance tables or stored aggregates were introduced.

## Source Of Truth

Official balances use:

- `AccountingJournalEntryLine.debitAmount`
- `AccountingJournalEntryLine.creditAmount`
- only entries with `AccountingJournalEntry.status = posted`
- tenant-scoped snapshots loaded by the Accounting persistence repository

Draft entries are excluded from official reports.

## Date Scope

Report queries support:

- `fromDate`
- `toDate`
- optional account filtering
- optional journal filtering

The read model distinguishes:

- opening balance: posted movements before `fromDate`;
- period debit: posted debits inside the selected period;
- period credit: posted credits inside the selected period;
- closing balance: opening balance plus period movements.

Date-only values are interpreted as full-day boundaries.

## Amount Precision

Reports use the existing Accounting amount utilities:

- canonical decimal strings;
- integer minor-unit calculations with `BigInt`;
- no floating-point totals.

The runtime validation covers the `0.10 + 0.20 - 0.30` case.

## Server Read Boundary

Added repository helpers:

- `getAccountingGeneralLedger()`
- `getAccountingTrialBalance()`

Added API operations to the existing Accounting persistence endpoint:

- `POST /api/persistence/accounting` with `operation: "getGeneralLedger"`
- `POST /api/persistence/accounting` with `operation: "getTrialBalance"`

The tenant/company scope is still resolved server-side through `requirePersistenceTenantScope()`.

## Validation Coverage

Runtime validation covers:

- simple balanced posted entry;
- multiple posted entries;
- draft exclusion;
- tenant isolation;
- date filtering with opening, period and closing balances;
- decimal precision without floating-point drift;
- grand Trial Balance reconciliation.

## Future Extensions

Future accounting sprints can build on this foundation to add:

- Chart of Accounts workspace;
- manual journal entry workspace;
- Finance navigation activation;
- source-document posting from Sales, Procurement and Inventory;
- financial statements;
- localization packs;
- fiscal periods;
- reconciliation.

None of those are part of SPR-431.

## Known Limitations

- No Finance UI is active.
- No automatic posting from Sales, Procurement, Inventory or Payments.
- No fiscal period engine.
- No P&L or Balance Sheet.
- No VAT reporting.
- No multi-currency revaluation.
- Account-filtered Trial Balance reports may not globally reconcile when only part of an entry's accounts are selected; this is expected for filtered analysis views.
